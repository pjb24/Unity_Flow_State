# 목적

프로젝트에서 검증 작업을 수행할 때 적용하는 규칙을 정의한다.

검증의 신뢰성을 유지하기 위한 기준을 정의한다.

작업 완료 여부를 판단하는 기준을 정의한다.

---

# 적용 범위

이 문서의 규칙은 프로젝트의 모든 검증 작업에 적용한다.

예외가 필요한 경우 별도의 Rule 문서에서 정의한다.

---

# 검증 원칙

구현이 완료된 후 반드시 검증을 수행한다.

검증은 확인 가능한 사실을 기준으로 수행한다.

추측을 검증 결과로 기록하지 않는다.

검증 대상의 책임 범위를 벗어나지 않는다.

관련 문서와 구현이 일치하는지 함께 확인한다.

---

# 검증 대상 선정 기준

이번 작업으로 직접 변경한 기능을 검증한다.

변경으로 영향을 받을 수 있는 기존 기능을 함께 검증한다.

관련 System과 Feature가 있는 경우 함께 검증한다.

문서가 변경된 경우 문서 내용도 함께 검증한다.

검증 범위는 변경 영향 범위를 기준으로 결정한다.

---

# 검증 기준

문서에 정의된 동작과 구현 결과가 일치하는 경우 정상으로 판단한다.

요구사항을 만족하는 경우 정상으로 판단한다.

문서와 구현이 다르게 동작하는 경우 비정상으로 판단한다.

확인되지 않은 사항은 정상으로 판단하지 않는다.

변경하지 않은 기능이 정상이라고 추측하여 검증 결과를 작성하지 않는다.

검증 결과에는 확인한 사실만 기록한다.

---

# 회귀 검증 기준

기존 기능에 영향을 줄 수 있는 변경이 있는 경우 회귀 검증을 수행한다.

공통 구조를 수정한 경우 관련 기능을 함께 검증한다.

변경 영향이 없는 경우 회귀 검증을 생략할 수 있다.

회귀 검증 생략 여부는 변경 영향 범위를 기준으로 판단한다.

---

# 작업 완료 기준

작업 범위의 구현이 완료되어야 한다.

관련 문서와 구현이 일치해야 한다.

확인되지 않은 사항이 없어야 한다.

검증 중 발견한 문제는 수정 여부와 관계없이 검증 결과에 기록한다.

추가 수정이 필요한 경우 작업 완료를 선언하지 않는다.

추가 검증이 필요한 경우 작업 완료를 선언하지 않는다.

검증 과정에서 새로운 문제가 발견된 경우 작업 범위를 임의로 확장하지 않는다.

새로운 문제는 별도의 작업 대상으로 분리한다.

검증 결과를 기록한 후 작업 완료를 선언한다.

---

# 금지 사항

검증하지 않은 기능을 정상으로 판단하지 않는다.

확인되지 않은 내용을 검증 결과로 기록하지 않는다.

회귀 검증이 필요한 경우 이를 생략하지 않는다.

근거 없이 작업 완료를 선언하지 않는다.

문서와 구현의 불일치를 확인하고도 그대로 작업 완료를 선언하지 않는다.

검증 과정에서 발견한 새로운 문제를 작업 범위를 벗어나 임의로 수정하지 않는다.
