# 목적

프로젝트에서 사용하는 로그 작성 규칙을 정의한다.

로그의 일관성을 유지하기 위한 기준을 정의한다.

로그를 통해 문제를 추적할 수 있는 기준을 정의한다.

---

# 적용 범위

이 문서의 규칙은 프로젝트의 모든 로그에 적용한다.

예외가 필요한 경우 별도의 Rule 문서에서 정의한다.

---

# 로그 작성 원칙

로그는 문제 추적과 원인 분석에 필요한 경우에만 작성한다.

정상 동작을 반복적으로 기록하는 로그는 작성하지 않는다.

로그는 발생한 사실만 기록한다.

추측이나 예상 원인을 로그에 포함하지 않는다.

동일한 상황에서 동일한 의미의 로그를 중복 작성하지 않는다.

---

# 로그 레벨 사용 기준

## Log

일반적인 개발 확인이 필요한 정보를 기록한다.

반복적으로 출력되는 로그는 최소화한다.

---

## Warning

복구 가능한 문제를 기록한다.

폴백이 발생한 경우 반드시 Warning 로그를 기록한다.

예상과 다른 입력이나 상태이지만 시스템이 계속 동작 가능한 경우 Warning 로그를 기록한다.

---

## Error

복구할 수 없는 오류를 기록한다.

정상적인 기능 수행이 불가능한 경우 Error 로그를 기록한다.

예외(Exception)로 인해 기능이 정상적으로 수행되지 못한 경우 Error 로그를 기록한다.

---

# 로그 내용 작성 기준

로그에는 발생한 사실을 포함한다.

로그에는 문제를 식별할 수 있는 최소 정보를 포함한다.

로그에는 추측한 원인을 포함하지 않는다.

로그 메시지는 동일한 상황에서 항상 동일한 의미를 가지도록 작성한다.

로그 메시지는 간결하고 명확하게 작성한다.

---

# 폴백 처리 규칙

폴백이 발생한 경우 반드시 Warning 로그를 기록한다.

Warning 로그에는 폴백이 발생한 사실을 포함한다.

가능한 경우 폴백이 발생한 원인을 함께 기록한다.

무음(Silent) 폴백은 허용하지 않는다.

폴백이 정상 동작처럼 보이도록 처리하지 않는다.

---

# 예외 상황 로그 기준

복구 가능한 예외는 Warning 또는 Error 기준에 따라 기록한다.

복구 불가능한 예외는 Error 로그를 기록한다.

예외를 무시하고 로그를 남기지 않는 것을 허용하지 않는다.

동일한 예외를 반복적으로 출력하는 구조를 만들지 않는다.

---

# 디버그 로그 사용 기준

디버그 로그는 개발 및 조사 과정에서만 사용한다.

문제 위치를 확인하기 위한 임시 디버그 로그는 사용할 수 있다.

임시 디버그 로그는 문제 해결 후 제거한다.

작업 완료 시 불필요한 디버그 로그는 제거한다.

릴리스 환경에서는 디버그 로그를 남기지 않는다.

문제 분석에 반드시 필요한 디버그 로그만 유지한다.

---

# 금지 사항

확인되지 않은 원인을 로그에 작성하지 않는다.

동일한 의미의 로그를 여러 번 출력하지 않는다.

동일한 원인에 대해 중복 로그를 반복적으로 출력하지 않는다.

불필요한 로그를 남기지 않는다.

로그 없이 예외를 무시하지 않는다.

폴백을 로그 없이 수행하지 않는다.

Error 상황을 Warning 또는 Log로 축소하여 기록하지 않는다.

로그를 통해 프로그램의 정상 동작 순서를 추적하는 구조를 만들지 않는다.
