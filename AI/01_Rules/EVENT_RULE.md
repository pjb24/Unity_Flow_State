# 목적

프로젝트에서 사용하는 이벤트 규칙을 정의한다.

이벤트 사용 기준을 정의한다.

이벤트 책임을 정의한다.

---

# 적용 범위

이 문서의 규칙은 프로젝트의 모든 이벤트에 적용한다.

예외가 필요한 경우 별도의 Rule 문서에서 정의한다.

---

# 이벤트 사용 기준

이벤트는 발생 주체와 처리 주체를 분리해야 하는 경우에 사용한다.

이벤트는 한 객체의 상태 변화나 동작 결과를 다른 객체가 알아야 하는 경우에 사용한다.

이벤트는 직접 참조를 줄여도 동작 흐름이 명확하게 유지되는 경우에 사용한다.

단순한 1:1 호출이며 호출 대상이 명확한 경우 이벤트를 사용하지 않는다.

호출 순서가 반드시 보장되어야 하는 핵심 게임 흐름에는 이벤트를 우선 사용하지 않는다.

---

# 이벤트 생성 규칙

새로운 이벤트는 기존 이벤트로 표현할 수 없는 의미를 가지는 경우에만 생성한다.

이벤트를 새로 생성하기 전에 기존 이벤트로 표현 가능한지 먼저 확인한다.

기존 이벤트의 의미를 변경하여 다른 용도로 재사용하지 않는다.

동일한 의미의 이벤트를 중복 생성하지 않는다.

이벤트 하나는 하나의 의미만 가진다.

여러 의미를 하나의 이벤트에 포함하지 않는다.

항상 함께 발생하는 동일 의미의 이벤트는 하나로 통합한다.

---

# 이벤트 명명 규칙

이벤트 이름은 발생한 사실을 기준으로 작성한다.

이벤트 이름은 `On` 접두어를 사용하지 않는다.

이벤트 이름은 완료된 상태를 의미하도록 작성한다.

예시

```text
StageStarted
StageCleared
PlayerDied
SlideStarted
SlideEnded
```

---

# 이벤트 등록 규칙

이벤트는 외부에 직접 노출하지 않는다.

이벤트 등록은 `AddListener()`를 통해서만 수행한다.

Unity `MonoBehaviour`에서는 일반적으로 `OnEnable()`에서 등록한다.

동일한 Listener를 중복 등록하지 않는다.

---

# 이벤트 해제 규칙

이벤트 해제는 `RemoveListener()`를 통해서만 수행한다.

Unity `MonoBehaviour`에서는 일반적으로 `OnDisable()`에서 해제한다.

등록한 Listener는 반드시 해제한다.

해제되지 않는 Listener를 남기지 않는다.

---

# 이벤트 책임 원칙

이벤트는 발생한 사실만 전달한다.

이벤트는 이후 처리 방식을 결정하지 않는다.

이벤트 발생자는 수신자를 알지 않는다.

이벤트 수신자는 자신의 책임 범위 안에서만 처리한다.

이벤트 데이터에는 처리에 필요한 최소 정보만 포함한다.

불필요한 객체 참조를 이벤트 데이터에 포함하지 않는다.

---

# 이벤트 의존성 원칙

이벤트는 직접 참조를 줄이기 위한 용도로 사용한다.

이벤트를 사용하여 양방향 의존성을 만들지 않는다.

이벤트를 사용하여 실행 흐름을 숨기지 않는다.

이벤트 체인이 길어져 흐름 추적이 어려운 구조를 만들지 않는다.

핵심 게임 진행 흐름은 이벤트만으로 연결하지 않는다.

---

# 금지 사항

`public event`를 직접 노출하지 않는다.

외부에서 `+=`, `-=`를 사용하여 이벤트를 구독하거나 해제하지 않는다.

외부에서 이벤트를 직접 호출할 수 있도록 만들지 않는다.

익명 함수를 Listener로 등록하지 않는다.

해제할 수 없는 Listener를 등록하지 않는다.

이벤트 내부에서 다른 System의 상태를 직접 변경하지 않는다.

단순 함수 호출을 이벤트로 대체하지 않는다.

이벤트 발생 순서에 의존하는 구조를 만들지 않는다.
