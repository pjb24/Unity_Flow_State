# 목적

AI가 프로젝트에서 따라야 하는 최상위 작업 원칙을 정의한다.

AI가 작업을 수행할 때 우선해야 하는 판단 기준을 정의한다.

AI가 프로젝트 문서를 사용하는 원칙을 정의한다.

---

# 적용 범위

이 문서의 규칙은 프로젝트의 모든 작업에 적용한다.

다른 Rule 문서는 이 문서의 원칙을 기준으로 작성한다.

---

# 작업 원칙

프로젝트 문서에 정의된 내용을 우선한다.

확인되지 않은 내용을 추측하여 구현하거나 문서에 작성하지 않는다.

문서에 정의되지 않은 내용을 AI가 임의로 보완하거나 추가하지 않는다.

필요한 정보가 부족한 경우 추측하지 않고 사용자에게 확인을 요청한다.

작업 요청 범위를 벗어나는 수정은 수행하지 않는다.

작업으로 인해 관련 문서의 내용이 변경되는 경우 필요한 문서를 함께 수정한다.

작업 대상의 책임 범위를 벗어나는 변경을 수행하지 않는다.

기존 구조를 충분히 검토한 후 필요한 경우에만 새로운 구조를 추가한다.

기존 구조로 해결 가능한 경우 기존 구조를 우선 사용한다.

동일한 목적의 구조를 중복 생성하지 않는다.

문서와 구현의 일관성을 유지한다.

---

# 판단 원칙

여러 구현 방법이 가능한 경우 구조의 단순성과 유지보수성을 우선한다.

책임이 명확하게 분리되는 구조를 우선한다.

확장성을 위해 현재 구조를 과도하게 복잡하게 만들지 않는다.

프로젝트 규모에 적합한 설계를 우선한다.

---

# 문서 사용 원칙

Project 문서는 프로젝트 수준의 정보를 확인하거나 수정할 때 사용한다.

Rules 문서는 프로젝트 규칙을 확인하거나 수정할 때 사용한다.

System 문서는 특정 System의 책임을 확인하거나 수정할 때 사용한다.

Feature 문서는 특정 Feature의 규칙을 확인하거나 수정할 때 사용한다.

Task 문서는 작업 결과를 기록하거나 기존 작업 이력을 확인할 때 사용한다.

Template 문서는 새로운 문서를 생성할 때만 사용한다.

---

# 문서 관리 원칙

새로운 문서는 기존 문서의 책임으로 표현할 수 없는 경우에만 생성한다.

기존 문서의 책임 범위에 해당하는 내용은 기존 문서를 수정한다.

문서는 책임이 달라지는 경우에만 분리한다.

책임이 동일한 문서는 통합을 우선 검토한다.

동일한 내용을 여러 문서에 중복 작성하지 않는다.

---

# Rule 적용 원칙

작업과 관련된 Rule 문서를 적용한다.

여러 Rule 문서가 동시에 적용되는 경우 AI_RULE.md를 최우선으로 적용한다.

Rule 간 내용이 충돌하는 경우 문서의 책임 범위를 기준으로 적용한다.

적용 가능한 Rule이 없는 경우 기존 Rule을 임의로 확장 해석하지 않는다.

---

# 예외 처리 원칙

기존 규칙으로 해결할 수 없는 경우에만 예외를 허용한다.

예외가 필요한 경우 기존 구조를 최대한 유지하는 방향을 우선한다.

예외 처리가 반복되는 경우 새로운 Rule 또는 문서 분리가 필요한지 검토한다.
