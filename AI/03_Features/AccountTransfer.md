# 기능 개요

## 기능명

AccountTransfer

---

## 목적

Anonymous 계정 사용자가 외부 ID 없이 현재 기기에서 새 기기로 하나의 논리 계정 연결을 이전할 수 있도록 한다.

---

# 기능 규칙

- 공개 번호는 서버 소유 논리 계정에 귀속하며, Anonymous Player ID와 직접 동일시하지 않는다.
- 논리 계정은 같은 환경에서 한 번에 하나의 활성 Player ID만 가진다.
- 복구 제한 동의 뒤 Anonymous 인증이 성공하면 서버는 즉시 해당 논리 계정의 공개 번호를 발급하거나 기존 번호를 반환한다.
- 공개 번호는 환경별로 독립된 10자리 고정 십진 문자열 `0000000001`~`9999999999`다. 선행 0을 표시하며 서버·Client·직렬화 경계에서 문자열로 유지한다.
- 공개 번호는 재발급하거나 다른 논리 계정에 재사용하지 않는다.
- 기존 계정은 최초 Anonymous 인증 때 번호를 발급하며, 기존 Leaderboard 행이 처음 조회될 때도 서버가 번호를 발급해 표시한다.
- 공개 번호 발급 또는 조회 실패는 안전한 Error와 Retry로 표시한다. 내부 Player ID, 마스킹 ID 또는 다른 계정 번호를 표시하지 않는다.
- 계정 안내와 Leaderboard 행은 공개 번호를 정확한 10자리 문자열로 표시하며, 현재 C의 행만 `<공개 번호> (You)`로 표시한다. 번호가 없거나 형식이 맞지 않으면 행·안내 전체를 Error와 Retry로 처리한다.
- 공개 번호 안내에는 `공개 번호만으로 계정을 복구할 수 없습니다. 이전 코드와 인증값을 사용하세요.`를 표시한다. 번호 발급·조회 Error는 Offline 플레이·Run 시작을 차단하지 않는다.
- 활성 기기만 기기 이전을 요청할 수 있다. 서버는 요청 즉시 계정을 `TransferPending`으로 잠근다.
- 제출 처리 예약 또는 C ledger의 진행 중 제출이 있으면 서버는 이전을 시작하지 않고 해당 처리의 확정·복구 후 재시도를 요구한다.
- `TransferPending` 중에는 이전 취소와 이전 완료에 필요한 요청 외의 온라인 기록 제출·조회·추가 이전 요청을 허용하지 않는다.
- 서버는 Crockford Base32의 8자리 이전 코드(`ABCD-2345`)와 별도 9자리 십진 인증값을 발급한다. 생성값은 `I`, `L`, `O`, `U`를 쓰지 않으며 입력의 `O`는 `0`, `I`·`L`은 `1`로 정규화한다. 인증값의 선행 0은 유지한다. 활성 코드 digest는 환경별로 유일해야 하며, 발급 충돌 시 서버가 새 값을 다시 생성한다.
- 서버는 이전 코드·인증값 원문을 저장·로그·일반 오류에 남기지 않는다. 서버 보유 비밀을 사용하는 HMAC 검증값과 코드 조회용 digest만 보관한다.
- 이전 자격 증명은 서버 발급 시각부터 90일 뒤 만료한다. 인증 실패 횟수는 제한하지 않으며, 같은 이전 요청의 반복 검증은 마지막 시도부터 5초 이상 지난 경우에만 허용한다.
- `TransferPending`의 활성 A는 새 이전 요청을 만들지 않지만 기존 이전의 자격 증명을 재발급할 수 있다. 재발급은 같은 이전 요청의 이전 코드·인증값을 즉시 무효화하고 새 값만 유효하게 한다.
- 새 기기는 Anonymous 인증 후 이전 코드와 인증값으로 연결을 요청한다. 서버가 검증에 성공하면 이전 자격 증명을 즉시 비활성화하고 활성 Player ID를 새 기기로 교체한다.
- 새 기기의 임시 논리 계정에 온라인 기록이 있어도 C에 연결할 수 있다. 기존 온라인 기록·번호·Leaderboard 행은 기존 논리 계정에 그대로 남기며 C와 병합·복사·삭제하지 않는다. Local Save Pending이 있으면 C에 연결하지 않고, 사용자는 먼저 Pending을 확정 처리하거나 명시적으로 폐기해 Pending을 0건으로 만들어야 한다.
- Local Save Pending 차단 시 이전 화면은 `이 기기에 전송 대기 중인 기록이 있습니다. 전송을 완료하거나 폐기한 뒤 계정 이전을 다시 시도하세요.`를 표시하고 C 연결을 요청하지 않는다.
- C 연결이 완료되면 새 기기의 Player ID는 C에만 연결된다. 새 기기의 기존 논리 계정은 활성 Player ID가 없는 상태로 남으며, 해당 기존 온라인 기록을 C에서 조회·제출하거나 공개 번호만으로 복구하지 않는다.
- 이전 완료·취소·만료는 하나의 이전 요청에서 먼저 서버에 확정된 terminal 상태가 우선한다. 완료 뒤 같은 B의 동일 요청 재호출은 이미 완료된 결과만 반환하며, 다른 B·A의 후속 완료·취소는 연결을 변경하지 않는다.
- 이전 완료 뒤 이전 기기는 `활성 기기 아님` 오류를 받고 해당 논리 계정의 온라인 기능을 사용할 수 없다. 이전 기기는 새 Anonymous 계정으로 시작한다.
- 이전 기기에서 만료 전 취소하면 잠금을 해제하고 기존 연결을 유지한다. 만료되면 서버는 기존 연결을 복원하고 이전 자격 증명을 폐기한다.
- 이전 기기를 사용할 수 없어 이전 자격 증명을 발급할 수 없는 경우 공개 번호만으로 복구하지 않는다.
- Local Save의 Settings·Pending은 이전하지 않는다. Pending이 있으면 이전을 시작하지 않으며, 먼저 확정 처리하거나 사용자가 명시적으로 폐기해야 한다.
- B의 이전 완료가 서버에서 확인되면 B의 로컬 개인 최고 기록은 C의 서버 귀속 개인 최고 기록으로 완전히 덮어쓴다. C에 서버 개인 최고가 없으면 B의 해당 로컬 개인 최고를 비운다. B의 이전 전 개인 최고는 유지·병합하지 않는다.
- 이전 코드·인증값·C의 내부 식별자·이전 상태는 Local Save에 저장하지 않는다. 이전 화면이 닫히거나 앱이 재시작되면 자격 증명 원문을 복원하지 않는다.
- A에서 이전 완료가 서버로 확인되면 A는 C 관련 표시 캐시와 로컬 개인 최고를 지우고 Unity Authentication 세션 토큰을 제거한 뒤 새 Anonymous Player로 인증한다. A의 Settings·튜토리얼은 기기 로컬 자료로 남는다.
- B에서 이전 완료가 서버로 확인되면 B는 이전 전 임시 계정의 표시 캐시를 지우고 현재 인증 Player ID로 C 연결·공개 번호·서버 귀속 개인 최고 기록을 다시 조회해 로컬 개인 최고를 덮어쓴다. Pending 0건 조건에서만 이전을 요청할 수 있다.
- 기기 이전은 A에서 B로 Leaderboard 기록을 이전하지 않는다. 계정 C에 영구 귀속된 고정 Leaderboard 소유 행을 계속 사용한다.
- 신규 계정의 고정 Leaderboard 소유 ID는 서버가 계정 C 생성 때 별도로 만든 불투명 UUID v4이며, 공개 번호·C·Anonymous Player ID와 동일시하지 않는다. 기존 온라인 자료의 최초 전환은 기존 UGS Player ID 행을 고정 소유 행으로 승계한다.
- 활성 연결 교체와 계정 C의 고정 Leaderboard 행은 분리된 데이터가 아니다. 기기 이전 뒤 별도 Leaderboard 기록 복구를 수행하지 않는다.
- 기기 이전은 기록을 새로 제출하거나 동점·서버 수락 시각 metadata를 변경하지 않는다.
- 환경을 넘는 기기 이전은 허용하지 않는다.
- 이전 요청·성공·취소·만료·실패 횟수와 최소 식별 정보만 서버에 기록한다. 인증값 원문, 인증 토큰, 내부 Player ID를 UI·일반 로그·고객센터 대화에 노출하지 않는다.
- 감사에는 이벤트·결과·서버 생성 이전 ID·환경·서버 시각·실패 누적 수와 안전한 사유 분류만 남긴다. 코드 원문·인증값·HMAC·digest·공개 번호·전체 요청 본문은 남기지 않는다.
- verification과 production의 논리 계정·공개 번호·이전 자격 증명·감사 자료는 서로 승계하거나 조회하지 않는다.

# 시작 조건

- 현재 활성 기기가 기기 이전을 요청한다.

---

# 종료 조건

## 정상 종료

- 새 기기가 논리 계정의 유일한 활성 연결이 된다.
- 이전이 취소되거나 만료되어 기존 연결이 유지된다.

## 강제 종료

- Application 종료 뒤에도 서버의 이전 상태를 유지한다.

---

# 수행 결과

- 새 활성 기기는 이전 전 논리 계정의 공개 번호를 사용한다.
- 이전 기기는 해당 논리 계정의 온라인 기능을 사용하지 못한다.

---

# 예외 사항

- 현재 활성 기기가 아닌 요청은 이전을 시작하거나 취소할 수 없다.
- 유효하지 않거나 비활성·만료된 이전 자격 증명은 연결을 교체하지 않는다.
- `TransferPending` 중인 계정은 온라인 기록 기능을 수행하지 않는다.

---

# 관련 System

- AccountConnectionSystem
- RecordSubmissionSystem

---

# 제약 사항

- 공개 번호는 계정 복구 또는 이전 자격 증명이 아니다.
- 기기 이전은 외부 ID 계정을 사용하지 않는다.
- 기기 이전은 계정 C의 고정 Leaderboard 소유 행을 변경하지 않는다.

---

# 검증 항목

- Anonymous 인증 직후 공개 번호가 발급 또는 재조회되는지 확인한다.
- 환경별 번호 유일성, 10자리 선행 0 표시, 재요청 시 번호 유지와 다른 계정 재사용 금지를 확인한다.
- 활성 기기만 이전을 시작·취소할 수 있고 `TransferPending`에서 온라인 기록 요청이 차단되는지 확인한다.
- 이전 자격 증명의 90일 만료, 새 코드 발급 뒤 즉시 무효화, 5초 반복 제한과 실패 횟수 무제한을 확인한다.
- 이전 성공 뒤 새 기기만 활성 연결이 되고 이전 자격 증명이 재사용되지 않으며 이전 기기 요청이 거부되는지 확인한다.
- Pending이 있을 때 이전을 시작하지 않고, 공개 번호만으로 연결을 교체하지 않는지 확인한다.
- 기기 이전 뒤에도 계정 C의 고정 Leaderboard 소유 행과 기존 동점·서버 수락 시각 metadata가 유지되는지 확인한다.

# 문서 작성 원칙

현재 Feature의 정의만 작성한다.

Feature의 규칙만 작성한다.

System의 책임을 작성하지 않는다.

구현 방법을 작성하지 않는다.

작업 기록을 작성하지 않는다.

변경 이력을 작성하지 않는다.

추측을 작성하지 않는다.

동일한 내용을 여러 섹션에 중복 작성하지 않는다.

Feature 하나당 문서 하나를 사용한다.
