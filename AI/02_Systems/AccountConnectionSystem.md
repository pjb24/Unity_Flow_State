# 시스템 개요

## 시스템명

AccountConnectionSystem

---

## 목적

서버 소유 논리 계정과 현재 활성 Anonymous Authentication Player ID의 연결을 관리한다.

공개 번호의 계정 귀속과 기기 이전 중 연결 상태를 관리한다.

---

# 시스템 책임

- 논리 계정, 공개 번호와 현재 활성 Player ID의 연결을 관리한다.
- Anonymous 인증 성공 뒤 공개 번호 발급·조회 요청 경계를 관리한다.
- 기기 이전 요청, 이전 자격 증명 상태, 연결 교체와 이전 자격 증명 소진을 관리한다.
- 활성 Player ID가 아닌 요청을 온라인 기록 서비스 경계에서 거부할 수 있는 연결 상태를 제공한다.
- 인증된 호출자와 환경에서 논리 계정을 찾고, 역방향 매핑과 계정 본문의 활성 연결을 대조한다.

---

# 시작 조건

- Anonymous Authentication이 성공한다.
- 활성 기기가 공개 번호 조회 또는 기기 이전을 요청한다.
- 새 기기가 서버 발급 이전 자격 증명을 제출한다.

---

# 종료 조건

## 정상 종료

- 공개 번호가 논리 계정에 귀속된다.
- 기기 이전이 완료·취소 또는 만료된다.

## 강제 종료

- Application이 종료된다. 서버에 보관된 연결과 이전 상태는 유지된다.

# 제약 사항

- 논리 계정은 같은 환경에서 동시에 하나의 활성 Player ID만 가진다.
- 이전 대상 Player ID가 이미 가진 임시 논리 계정의 온라인 자료는 C와 병합하지 않는다. Local Save Pending이 없을 때만 해당 Player ID를 C에 연결하며, 기존 논리 계정은 활성 Player ID가 없는 상태로 남긴다.
- 온라인 제출은 활성 연결·연결 버전과 같은 Account의 단일 서버 작업 예약을 확인한 뒤에만 수행한다. 연결 교체는 예약 또는 C ledger의 진행 중 제출이 없을 때만 시작한다.
- 공개 번호는 논리 계정에 영구 귀속하며 Player ID 연결 교체로 재발급·재사용하지 않는다.
- 고정 Leaderboard 소유 ID는 신규 계정에서는 서버가 생성한 불투명 UUID v4이고, 기존 온라인 자료의 최초 전환에서는 기존 UGS Player ID를 승계한다. 어느 경우든 논리 계정에 영구 귀속하고 기기 이전으로 변경하지 않는다.
- 이전 자격 증명의 원문은 서버에 영구 보관하지 않는다.
- 환경을 넘는 연결·공개 번호·이전 자격 증명 이전을 수행하지 않는다.
- 클라이언트가 전달한 논리 계정 ID·공개 번호·고정 Leaderboard 소유 ID를 접근 권한의 근거로 사용하지 않는다.
- Cloud Code 실행 context의 Project ID·Environment ID가 Account와 Transfer의 저장 환경 모두와 일치하지 않으면 요청을 처리하지 않는다.
- 감사 출력은 이전 이벤트·결과·서버 생성 이전 ID·환경·서버 시각·실패 누적 수와 안전한 사유 분류로 제한한다. 자격 증명 원문·토큰·HMAC·digest·내부 Player ID·공개 번호는 일반 로그·오류·외부 지원 경로에 내보내지 않는다.
