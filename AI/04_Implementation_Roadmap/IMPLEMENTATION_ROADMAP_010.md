# 목적

Thirdparty 원본 애셋을 Git 형상 관리에서 제외하면서 의존성과 프로젝트 복원 가능성을 관리한다.

# 프로젝트 정보

## 프로젝트명

Flow State

## 목표

Roadmap 10 — Thirdparty 애셋 관리와 프로젝트 복원 체계.

계획 확정일: 2026-11-11. **계획 확정·구현 미착수**이며 각 Phase의 상태는 대기다.
선행: [Roadmap 9](IMPLEMENTATION_ROADMAP_009.md) 완료 후 순차 착수한다.
공통 순서·승인/검증 경계는 [로드맵 안내](README.md)를 따른다.

## 범위 밖

Thirdparty 구매/계약 체결의 자동 승인, 원본 삭제, Git 과거 이력 재작성, 모든 Unity Package 선언의 일괄 제외. 현재 추적 해제와 과거 이력 삭제는 별개이며 파괴적 조작은 별도 승인한다.

# 개발 단계

## Phase 1. 원본·프로젝트 소유 자료 경계 확정

### 목표

제외할 파일과 유지할 도입 정보를 구분한다.

### 구현 대상

- 기존 Thirdparty/패키지·추적 상태·배포물/의존성의 목록 조사.
- 원본/파생 자료·자체 코드/설정·연결용 애셋과 .meta 관리 범위 결정.
- 제품/버전·취득 경로·사용 조건·도입 담당 및 재취득 가능성 확인.

### 완료 조건

- 단순 폴더명뿐 아니라 실제 내용/출처를 기준으로 제외 범위가 정해져 있다.
- Unity Package 의존성 선언과 lock 정보 등 복원용 정보의 관리 범위가 정해져 있다.
- 외부 원본 복사본/파생물의 관리 판단과 비밀값/유료 원본을 포함하지 않는 기록 범위가 명확하다.

### 상태

대기 — 구현/실행 검증 미착수.

## Phase 2. 형상 관리 제외와 도입·복원 절차

### 목표

원본 유입을 막고 동일 의존성을 다시 준비할 수 있게 한다.

### 구현 대상

- 추적 중/미추적 Thirdparty 구분과 제외 규칙/유입 검사 정비.
- 프로젝트 설정과 외부 원본의 분리 및 필요한 재적용 정보 관리.
- 버전·경로·GUID/Import 설정·참조 안정성을 포함한 도입/복원 절차 준비.

### 완료 조건

- 관리 대상 외부 원본이 현재 Git 추적/신규 staged 후보에 포함되지 않음을 검사할 수 있다.
- 애셋 누락/버전 불일치를 식별하고 적법하게 재도입할 수 있다.
- 외부 원본을 직접 수정하지 않는 확장 경계와 필요한 설정 재현 방법이 정리되어 있다.

### 상태

대기 — 구현/실행 검증 미착수.

## Phase 3. 독립 복원 검증과 후속 도입 인계

### 목표

기존 로컬 캐시에만 의존하지 않는 복원 가능성을 확인한다.

### 구현 대상

- 기존 작업본을 보존하는 별도 환경에서 checkout/의존성 도입 검증 계획.
- Prefab/Material/Animation/Scene 참조와 Import 설정 보존 확인.
- Roadmap 11~14에서 도입할 사운드/그래픽/UI 애셋에 적용할 점검 기준 인계.

### 완료 조건

- 필요한 외부 애셋 도입 후 대상 프로젝트가 누락 참조 없이 복원됨을 확인했다.
- 원본 비추적과 프로젝트 소유 파일 보존을 함께 검증했다.
- 복원 제약/수동 도입 단계와 검사 결과를 기록했다.

### 상태

대기 — 구현/실행 검증 미착수.
