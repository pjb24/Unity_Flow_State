# 목적

착지·실패·점수 획득의 확정 결과를 화면과 사운드로 전달해 플레이어가 자신의 행동 결과를 이해하도록 한다.

# 프로젝트 정보

## 프로젝트명

Flow State

## 목표

Roadmap 11 — 플레이어 피드백 강화.

계획 확정일: 2026-11-11. **계획 확정·구현 미착수**이며 각 Phase의 상태는 대기다.
선행: [Roadmap 10](IMPLEMENTATION_ROADMAP_010.md) 완료 후 순차 착수한다.
공통 순서·승인/검증 경계는 [로드맵 안내](README.md)를 따른다.

## 범위 밖

착지 판정 시간·물리·점수 공식 변경, 캐릭터/맵 전면 교체, 전체 UI 리디자인. 카메라 흔들림/섬광 등의 도입 여부와 강도 설정은 Phase 1에서 필요성을 확인한 뒤 결정한다.

# 개발 단계

## Phase 1. 피드백 범위와 공통 스타일 방향 확정

### 목표

전달할 결과와 Roadmap 12~14의 공통 표현 방향을 먼저 정한다.

### 구현 대상

- Normal Landing·Momentum Landing 성공·Collectible/점수 획득·Run 종료의 구분.
- 확인 가능한 종료 사유와 전달 문구/화면·사운드 역할 정리.
- 캐릭터/맵/UI의 공통 색상·명암·분위기·위험 표시 방향 확정. 구체 제품/표현 값은 이 단계에서 결정.

### 완료 조건

- 일반 착지를 모두 실패로 표현하지 않는 구분이 확정되어 있다.
- 사유를 판정할 수 없는 실패에 추측 원인을 표시하지 않는 범위가 정해져 있다.
- 12~14에서 이어받을 스타일 기준과 연출 과밀/가독성 조정 범위가 정해져 있다.

### 상태

대기 — 구현/실행 검증 미착수.

## Phase 2. 화면·사운드 결과 전달

### 목표

기존 판정 결과를 일관된 피드백으로 연결한다.

### 구현 대상

- 착지/획득/종료의 구별 가능한 시각·청각 표현.
- 동시/연속 발생 시 우선순위와 반복 재생/중복 표시 제어.
- 기존 Master Volume·Pause·Retry·새 Run 상태와 연동.

### 완료 조건

- 확정된 결과와 연출이 일치하고 점수/착지 판정을 연출이 다시 계산하지 않는다.
- 사운드/화면 표현이 조작과 위험 요소를 가리지 않는다.
- Pause·Retry·종료/화면 이동 뒤 잘못된 연출/사운드가 남지 않는다.

### 상태

대기 — 구현/실행 검증 미착수.

## Phase 3. 회귀·인지성 검증과 표현 교체 인계

### 목표

결과 전달 개선과 게임 규칙 보존을 함께 확인한다.

### 구현 대상

- 중복/상태 전환 자동 검증과 실제 시청각 구별 사용자 확인 분리.
- 현재 캐릭터/맵에서도 독립적으로 기능하는 피드백 후보 검증.
- Roadmap 12~14의 모델·Animation·Material·UI 교체 때 유지할 연동 경계 인계.

### 완료 조건

- 수치/발생 횟수/수명은 자동 검증, 실제 인지성·음량·가독성은 사용자 확인 근거가 있다.
- 기존 이동·판정·점수·제출 규칙이 보존된다.
- 구현 기능과 시각/사운드 교체 대상이 분리되어 있다.

### 상태

대기 — 구현/실행 검증 미착수.

# 현재 개발 진행 상태

없음. 계획 문서 확정은 구현 착수나 구현 완료가 아니다.

## 다음 작업

선행 Roadmap 완료 후 Phase 1의 범위/영향 대조와 세부 작업 계획을 준비한다.

## 보류된 작업

범위 밖 항목의 도입은 별도 범위 결정 전 수행하지 않는다.

## 완료된 단계

없음. 문서 작성만 완료했다.

# 구현 우선순위

1. 피드백 범위와 공통 스타일 방향 확정.
2. 화면·사운드 결과 전달.
3. 회귀·인지성 검증과 표현 교체 인계.

# 완료 기준

착지·실패·점수 획득의 확정 결과를 화면과 사운드로 전달해 플레이어가 자신의 행동 결과를 이해하도록 한다.
각 Phase의 완료 근거와 관련 문서 반영·회귀 검증 결과를 확보하고 범위 밖 기능/데이터 변경을 수행하지 않는다.
계획 승인만으로 실제 구현/사용자 검증·원격 배포·공개 개시가 승인되거나 성공한 것으로 기록하지 않는다.
