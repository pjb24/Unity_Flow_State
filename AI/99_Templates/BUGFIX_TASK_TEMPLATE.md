# Bug Fix Task Template

이 문서는 버그 수정 작업 기록 템플릿이다.

버그 수정 작업을 기록할 때 이 템플릿을 사용한다.

작성된 작업 기록은 `90_Tasks` 영역에 저장한다.

---

# 작업 정보

## 작업명

Bug Fix Task Name

---

## 작업 일자

YYYYMMDD

---

## 작업 담당자

담당자 이름

---

# 문제 현상

수정 대상 버그의 현상을 설명한다.

사용자가 확인한 현상을 설명한다.

예외가 발생한 상황을 설명한다.

재현 가능한 현상을 작성한다.

---

# 재현 조건

버그가 발생하는 조건을 설명한다.

버그를 재현하는 절차를 설명한다.

버그가 항상 발생하는지 설명한다.

버그가 간헐적으로 발생하는 경우 발생 조건을 설명한다.

---

# 원인 조사

버그 원인을 조사한 내용을 작성한다.

확인한 코드와 문서를 작성한다.

원인이라고 판단한 근거를 작성한다.

원인으로 판단하지 않은 내용은 작성하지 않는다.

추측은 작성하지 않는다.

---

# 원인

버그의 실제 원인을 작성한다.

원인은 하나 이상의 항목일 수 있다.

원인이 확인되지 않은 경우 원인을 추정하여 작성하지 않는다.

---

# 수정 내용

버그를 해결하기 위해 수정한 내용을 작성한다.

변경한 구조를 작성한다.

변경한 코드의 목적을 작성한다.

불필요한 구현 과정은 작성하지 않는다.

---

# 영향 범위

버그 수정으로 영향을 받는 System을 작성한다.

버그 수정으로 영향을 받는 Feature를 작성한다.

영향이 없는 영역은 작성하지 않는다.

---

# 검증 내용

버그 수정 후 수행한 검증을 작성한다.

버그가 재현되지 않는 것을 확인한 방법을 작성한다.

관련 기능의 회귀 검증 내용을 작성한다.

---

# 검증 결과

버그 수정 결과를 작성한다.

버그가 해결되었는지 작성한다.

추가 문제가 발생했는지 작성한다.

남아 있는 문제가 있는 경우 작성한다.

---

# 후속 작업

추가 수정이 필요한 경우 작성한다.

추가 조사 항목이 있는 경우 작성한다.

구조 개선이 필요한 경우 작성한다.

후속 작업이 없는 경우 "없음"을 작성한다.

---

# 관련 문서

참조한 Project 문서를 작성한다.

참조한 Rules 문서를 작성한다.

참조한 System 문서를 작성한다.

참조한 Feature 문서를 작성한다.

관련 문서가 없는 경우 "없음"을 작성한다.

---

# 관련 작업 기록

관련된 작업 기록이 있는 경우 작성한다.

관련 작업 기록이 없는 경우 "없음"을 작성한다.

---

# 작성 완료 기준

모든 섹션을 작성한다.

확인하지 않은 내용을 작성하지 않는다.

추측을 작성하지 않는다.

동일한 내용을 여러 섹션에 중복 작성하지 않는다.

작업 완료 후 아래 파일명 형식으로 `90_Tasks`에 저장한다.

```text
YYYYMMDD_<그 날 작업 번호>_작업명.md
```
