# Feature Task Template

이 문서는 Feature 작업 기록 템플릿이다.

Feature 구현 작업 또는 Feature 수정 작업을 기록할 때 이 템플릿을 사용한다.

작성된 작업 기록은 `90_Tasks` 영역에 저장한다.

---

# 작업 정보

## 작업명

Feature Task Name

---

## 작업 일자

YYYYMMDD

---

## 작업 담당자

담당자 이름

---

# 작업 목적

이번 작업을 수행한 목적을 작성한다.

새로운 Feature 구현인지 기존 Feature 수정인지 명확하게 작성한다.

---

# 작업 대상

작업 대상 Feature를 작성한다.

관련 System이 있는 경우 함께 작성한다.

---

# 작업 전 상태

작업을 시작하기 전 Feature의 상태를 작성한다.

수정 작업인 경우 기존 문제점 또는 변경이 필요한 이유를 작성한다.

신규 구현인 경우 "신규 구현"을 작성한다.

---

# 조사 내용

작업 전에 확인한 내용을 작성한다.

참조한 문서를 작성한다.

확인한 Feature 규칙과 관련 System을 작성한다.

추측은 작성하지 않는다.

---

# 작업 내용

구현하거나 수정한 내용을 작성한다.

변경한 기능 규칙의 요약을 작성한다.

변경 이유를 함께 작성한다.

구현 과정은 필요한 경우에만 작성한다.

---

# 영향 범위

이번 작업으로 영향을 받는 Feature를 작성한다.

이번 작업으로 영향을 받는 System을 작성한다.

영향이 없는 경우 "없음"을 작성한다.

---

# 검증 내용

작업 완료 후 수행한 검증 내용을 작성한다.

정상 동작을 확인한 항목을 작성한다.

회귀 검증을 수행한 경우 함께 작성한다.

---

# 검증 결과

검증 결과를 작성한다.

확인된 문제점이 있는 경우 작성한다.

미해결 사항이 있는 경우 작성한다.

모든 검증이 완료된 경우 명확하게 작성한다.

---

# 후속 작업

추가 구현이 필요한 경우 작성한다.

추가 수정이 필요한 경우 작성한다.

추가 조사가 필요한 경우 작성한다.

후속 작업이 없는 경우 "없음"을 작성한다.

---

# 관련 문서

참조한 Project 문서를 작성한다.

참조한 Rules 문서를 작성한다.

참조한 System 문서를 작성한다.

참조한 Feature 문서를 작성한다.

관련 문서가 없는 경우 "없음"을 작성한다.

---

# 관련 작업 기록

관련 작업 기록이 있는 경우 작성한다.

관련 작업 기록이 없는 경우 "없음"을 작성한다.

---

# 작성 완료 기준

모든 섹션을 작성한다.

확인하지 않은 내용을 작성하지 않는다.

추측을 작성하지 않는다.

동일한 내용을 여러 섹션에 중복 작성하지 않는다.

Feature 자체의 정의는 수정하지 않는다.

작업 기록에는 변경 요약만 작성한다.

Feature 정의 변경이 필요한 경우 Feature 문서를 함께 수정한다.

실제 정의 변경은 Feature 문서에 반영한다.

작업 완료 후 아래 파일명 형식으로 `90_Tasks` 영역에 저장한다.

```text
YYYYMMDD_<그 날 작업 번호>_작업명.md
```
